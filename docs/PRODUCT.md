# 제품 방향 업데이트 · 0.4

현재 우선 대상은 **공정 엔지니어의 레시피·실험 검토**입니다. 교육용 3D 모델을 유지하면서 서버 기반 버전·실험·동료 검토 워크스페이스를 추가했습니다. 구현과 운영 경계는 [운영 문서](OPERATIONS.md)를 기준으로 확인하세요. 아래 내용은 초기 포트폴리오 단계의 기획 기록으로, 서버 저장과 동료 검토는 이후 구현되었습니다.

# 포트폴리오와 상품화 방향

## 이번 제품의 목적

우선 사용자는 서비스를 판매하는 회사가 아니라 **직접 공정 시뮬레이터를 만든 취업 준비생**입니다. 프로젝트의 첫 성공 기준은 면접관에게 공정 이해, 모델 설계, 시각화, 실험 재현성, 기술적 한계를 설명할 수 있는 것입니다.

한 문장 소개: **“포토 공정의 변화를 장면·단면·불량 맵으로 연결하고, 가설과 실험을 재현 가능한 기록으로 만드는 가상 실습실입니다.”**

## 3분 데모

1. **30초 — 문제:** 공정 용어를 외워도 노광된 PR이 언제 없어지고 식각으로 어떻게 전사되는지 이해하기 어렵습니다.
2. **45초 — 시각화:** 노광과 현상을 차례로 선택해 잠상과 패턴 제거의 차이를 보여줍니다. 기준 비교에서 잔사를 확인합니다.
3. **45초 — 실험:** 초기 현상 잔사 미션에서 노광량·현상 시간을 한 번에 하나씩 변경하고 가설을 기록합니다.
4. **30초 — 통계:** 공정창 스윕, 시드 반복, 다이별 측정값을 보여줍니다.
5. **30초 — 한계와 확장:** 물리 TCAD가 아닌 공개 원리 기반 교육용 대체 모델임을 설명하고 실제 데이터 보정 계획을 제시합니다.

## 면접에서 설명할 기술적 결정

- 프레임워크·서버 의존성을 줄여 파일 실행과 빠른 시연이 가능하도록 구성했습니다.
- DOM 상태와 독립적인 공정 엔진을 분리해 입력→결과를 재현하고 검증할 수 있습니다.
- 시드를 고정해 레시피 A/B 비교에서 난수 변경이 개선처럼 보이는 문제를 줄였습니다.
- 현재 설정 미리보기와 마지막 실행 결과를 분리하고, 새로고침 후에도 구분을 유지합니다.
- Three.js로 각 장비의 독립 모델과 웨이퍼 이송·가공 타임라인을 만들고, SVG로 재료·마스크·단면 관계를 연결합니다.
- 사용자 가설을 출력할 때 HTML을 이스케이프하고, CSV의 수식 해석 가능 문자열을 중립화합니다.
- 계산값의 출처·가정·단위와 통계의 의미를 문서화합니다.

발표 시 ‘실제 팹 수율을 정확하게 예측했다’, ‘실제 IP를 통합했다’, ‘AI가 불량 원인을 진단한다’ 또는 ‘세계 최초’라고 소개하지 않습니다. 현재 구현은 그러한 검증을 하지 않았습니다.

## 상품성 가설

| 잠재 사용자 | 해결할 문제 | 후보 제공 가치 | 검증 방법 |
|---|---|---|---|
| 취업 준비생 | 실습 접근성과 면접에 쓸 문제 해결 사례 부족 | 실패 미션·실험 노트·재현 리포트 | 5–10명 관찰 인터뷰로 이해도와 완료율 확인 |
| 대학 강의·부트캠프 | 실습 장비 제약, 학생의 사고 과정 파악 어려움 | 과제 배포·실험 이력·교사용 평가 | 강사 2–3명과 한 수업 단위 파일럿 |
| 기업 입문 교육 | 장비 접근 전 용어·흐름 습득 | 조직별 시나리오·교육 모듈 | 교육 담당자 인터뷰 후 별도 검증 |

가격·전환율·시장 규모는 조사 없이 숫자로 만들어 넣지 않았습니다. 무료 기본 실습 + 유료 심화 미션/교육기관 운영 기능을 후보로 삼되, 지불 의향을 확인한 뒤 가격을 정합니다.

## 다음 개발 순서

1. **포토 실습 완성도:** PR 재료 선택, 프라이밍·EBR·냉각, 정렬 오차, 마스크 패턴 편집, 시간별 현상 전선, 모바일 렌더링 검증.
2. **물리 모델 강화:** 공중상(aerial image) 계산과 노광·초점 매트릭스, PR 반응과 현상 모델을 별도 모듈로 도입. 실측 대비 오차를 함께 표시.
3. **실험 설계:** 단일 변수 스윕을 2변수 dose–focus 매트릭스로 확장. 파라미터 변동과 시드 변동을 구분.
4. **실제 데이터:** 사용 조건이 확인된 계측 데이터로 보정하고 외부 검증 세트를 분리. 웨이퍼 맵 데이터는 패턴 분석 과제로 독립 연계.
5. **교육기관 기능:** 서버 저장·로그인·과제 배포·학습 기록·강사 피드백. 현재는 미구현.
6. **공정 확장:** 증착·이온주입·금속 배선·검사·패키징은 독립 모델과 테스트를 갖춘 후 추가.

## 아키텍처 확장 경계

```text
Recipe / Scenario
       │
       ▼
engine.js ──────▶ immutable result + per-die measurements
       │                           │
       ├── sweep / repeat          ├── SVG scene / section / map
       │                           └── stats / report
       ▼
local history (v2) ──▶ future API / database
```

3D 라이브러리로 Three.js를 도입했으며 공정 엔진은 분리되어 있습니다. 추후 계산 Web Worker, 서버 모델을 도입하더라도 레시피와 결과 스키마·모델 버전·시드는 유지하는 방향입니다. 상용 엔진을 호출하거나 클라우드 계산을 제공하는 기능은 현재 구현하지 않았습니다.
