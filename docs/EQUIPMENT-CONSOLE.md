# 장비 운전실 · 오프라인 이온 밀링 모델

기존 CMOS Fab와 별개로 `equipment.html`에서 사용합니다. 모델 버전은 `wf-equipment-0.1.0`입니다. 기존 Fab 기록, CMOS 엔진, 포토 실험실, 서버 검토 DB는 변경하지 않습니다. `index.html`에는 이동 링크만 추가했습니다.

## 사용 방법

1. 전용 서버 실행 후 `http://127.0.0.1:8766/equipment.html`을 엽니다. 이미 실행 중이던 서버는 새 화면의 정적 파일 허용 목록을 읽도록 한 번 재시작합니다.
2. 레시피를 편집하고 **설정 조건으로 실행**을 누릅니다. 예제 범위·전력 조합·냉각 조합 검사를 통과하면 전체 운전 응답을 먼저 계산하고 동작을 재생합니다.
3. 반입 → 진공 형성 → 조건 안정화 → 이온 밀링 → 냉각 → 압력 복귀 → 반출을 확인합니다. 기본값은 모델 시간 151초이며 기본 재생은 4배속입니다.
4. 이온원·셔터·스테이지·진공·냉각·이송부를 클릭하면 작용 설명이 나옵니다. 키보드 Tab 및 Enter/Space도 지원합니다.
5. 재생·일시정지·배속·슬라이더·단계 버튼·이벤트·차트로 시점을 탐색합니다. 숨겨진 탭은 일시정지합니다. 설정 변경은 새 계산에만 적용됩니다.
6. 진공 도달 실패, 가공 중 냉각 압력 저하, 빔 전류 추종 실패를 선택해 다시 실행합니다. 압력·빔·냉각·회전·틸트 채널에서 설정값과 응답을 비교합니다.
7. **운전 중단**은 현재 시점에서 가상 운전을 자르고 빔·셔터 명령을 차단합니다. 실제 센서 응답을 즉시 0으로 만들지 않고, 로봇 위치와 게이트를 마지막 상태에 유지합니다. 실제 하드웨어 비상 정지 모델은 아닙니다.
8. **운전 기록**은 현재 계산 전체 또는 불러온 로그 전체를 JSON으로 저장합니다. 재생 위치는 별도로 포함합니다. 중단했다면 중단 시점까지 저장합니다. 단순 일시정지는 기록을 자르지 않습니다.

브라우저 저장 키는 `waferflow-equipment-draft-v1`입니다. 레시피 초안과 고장 선택만 자동 저장하며, 센서 기록은 자동 업로드하지 않습니다. JSON 내보내기 또는 새 [레시피·실험 검토](EQUIPMENT-REVIEW.md)의 **검토 기록 보관**을 사용합니다. 후자를 선택하면 현재 계산 기록과 입력한 검토 정보를 인증된 서버에 보관합니다.

## 데이터 출처

PHM Society 2018 Ion Mill Etching의 **공개 채널 종류**를 참고했습니다. PHM 원본 행은 포함하지 않았습니다. 원본의 공학 단위는 비공개이며 재배포 조건도 확인되지 않았습니다. 이 앱의 Pa·V·mA·rpm·° 수치, 범위, 시간 상수, 전이 조건, 인터록, 장비 형상은 자체 제작 예제입니다. 삼성·SK하이닉스·제조사의 운전 데이터가 아닙니다.

ASML EXE:5200B와 SK하이닉스의 도입 발표는 자료 목록에서 확인할 수 있습니다. 이 노광 장비를 현재 이온 밀링 모델로 구동한다고 표시하지 않습니다. 상세 출처와 확보 범위는 [EQUIPMENT-DATA.md](EQUIPMENT-DATA.md)에 있습니다.

## 계산 범위

- 시간 간격 0.25초의 결정적 1차 지연 응답. 유체·플라즈마·열전달 해석 또는 식각 깊이 예측을 하지 않습니다.
- 진공 준비, 냉각, 빔 추종, 회전·기울기 안정 조건을 만족해야 다음 단계로 전이합니다. 시간 초과 또는 편차는 기록과 차단 상태를 만듭니다.
- 빔과 셔터는 별개 신호입니다. 안정화 단계에서는 빔을 준비하면서 셔터를 닫고, 가공 때 엽니다.
- 게이트 개방은 모델의 대기압 복귀 및 빔·회전 정지 조건을 요구합니다.
- `digital.wafer`는 스테이지 안착 여부입니다. 반입 전반과 반출 후반에는 웨이퍼가 로봇에 있습니다. 로봇 좌표는 0–1 정규화된 예제 위치이며 실제 축 좌표가 아닙니다.
- 내부 그림은 독립 SVG 절개 모형입니다. 제조사 CAD, 간섭·충돌 검증 모델이 아닙니다. 각도 표시와 회전 마커는 시각화입니다.
- 정상 완료는 **예제 시퀀스 완료**이며 실제 웨이퍼 투입 승인, 품질 판정 또는 장비 안전 검증을 의미하지 않습니다.

## 로그 교환 형식

`schema: "waferflow-equipment-trace-v1"`. 이 화면에서 내보낸 JSON을 전체 양식으로 사용합니다. 원본 PHM 파일을 직접 읽는 파서는 제공하지 않습니다. 공학 단위가 없는 원본에 임의 단위를 붙여 가져오면 안 됩니다.

```json
{
  "schema": "waferflow-equipment-trace-v1",
  "modelVersion": "external-log-v1",
  "profileId": "user-provided-tool",
  "units": { "pressurePa": "Pa" },
  "samples": [
    { "t": 0, "stage": "unknown", "values": { "pressurePa": 1.2 } },
    { "t": 1, "stage": "unknown", "values": { "pressurePa": 1.1 } }
  ],
  "events": [],
  "outcome": { "status": "completed", "reason": "제공된 로그 종료" },
  "duration": 1
}
```

위 숫자도 교환 형식 설명용 예제입니다. 실제 측정 데이터가 아닙니다.

- 파일 최대 8 MB, 샘플 2–15,000개, 모델 시간 0–1,800초, 이벤트 최대 5,000개입니다.
- `t`는 0부터 중복 없이 증가하는 초입니다. `duration`은 마지막 샘플 시각과 일치해야 합니다.
- 지원 채널과 단위: `pressurePa: Pa`, `beamVoltageV: V`, `beamCurrentMa: mA`, `heliumPressurePa: Pa`, `rotationRpm: rpm`, `tiltDeg: °`. 단위를 자동 추정·변환하지 않습니다.
- `stage`는 `load`, `pump`, `stabilize`, `process`, `cooldown`, `vent`, `unload`, `unknown` 중 하나입니다.
- 각 샘플의 `targets`, `digital` 및 최상위 `recipe`는 선택 사항입니다. 누락값을 0이나 성공으로 바꾸지 않습니다. `digital`의 `beam`, `shutter`, `pump`, `gate`, `wafer`는 불리언, `robot`은 0–1입니다. `shutter`, `gate`의 `true`는 열림입니다.
- 불러온 값은 실제 기록 간격대로 유지하며 중간 센서값을 보간하지 않습니다. 합성 모델의 응답만 시각화를 위해 보간합니다. 희소 값은 차트에서 끊어 표시합니다.
- 외부 파일은 출처 주장과 관계없이 **불러온 로그 · 출처 미검증**으로 표시합니다. 파일의 결과는 기록상의 결과이며 검증된 판정이 아닙니다.
- 가져오기에 실패하면 이전 화면·기록을 유지합니다. 불러온 레시피는 읽기 전용이며 예제 모델로 돌아오면 이전 초안을 복원합니다.

## 검증

`tests/equipment-engine-tests.mjs`는 정상 순서, 입력 오류, 단위·시간·구조 검증, 세 가지 이상 조건과 단계별 차단을 시험합니다. `tests/equipment-ui-tests.mjs`는 실제 UI 스크립트와 SVG를 LinkeDOM에서 구동해 입력·재생·중단·가져오기·저장 분리를 시험합니다. 결과 JSON은 `tests/equipment-*-results.json`입니다.

2026-09-18 확인: 장비 엔진 28개, 장비 UI 23개, 기존 CMOS 56개, 서버 검토 21개로 총 128개가 통과했습니다. 새 화면의 HTML·CSS·JS는 개발 서버에서 HTTP 200, DB 파일과 서버 소스는 HTTP 404를 확인했습니다. 현재 별도 실행 주소는 `http://127.0.0.1:8768/equipment.html`이며 기존 개발 서버 8766도 유지합니다. 브라우저 저장은 포트별로 분리되므로 기존 CMOS 기록은 원래 사용하던 8766 주소에서 확인합니다.

이 검증은 모델·DOM 동작 검증입니다. 실제 브라우저의 화면 배치, 그래픽 표시, 제조사 장비 데이터에 대한 정확도 검증은 별도입니다.
