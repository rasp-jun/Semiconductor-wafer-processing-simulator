# Memory Fab Integration — 메모리 공정 통합 검토

기본 화면은 이제 `index.html`의 메모리 팹 통합 공간입니다. 기존 CMOS 단면·117개 공정·브라우저 기록은 `cmos-lab.html`에서 그대로 사용합니다. 단일 이온 밀링 응답과 서버 검토는 `equipment.html`에 유지합니다.

## 제품이 다루는 문제

레시피 하나의 수치만 확인해서는 상류 공정 편차, 동일 챔버 경유 LOT, 후속 계측 보류와 생산 대기의 관계를 설명하기 어렵습니다. 이 화면은 **공정 조건 → 장비 배정 → LOT 이력 → 계측 규칙 → 후속 영향 → 대안 계획**을 한 흐름으로 묶습니다.

SK하이닉스와 같은 메모리 제조 기업에 제시할 가치는 이 연결을 짧은 시연으로 이해할 수 있다는 점입니다. 기업에 기존 MES·FDC·APC·가상 계측·스케줄링 시스템이 없다는 전제가 아니며, 시장에 없는 기술이라는 주장도 아닙니다. 특정 조직이 관심을 가질지 또는 도입할지는 실제 업무·데이터·평가에 달려 있습니다.

## 작동하는 시연

1. 기본 `HAR 챔버 깊이 편차` 계획을 엽니다. 첫 후속 보류 시점에서 시작합니다.
2. 팹 지도에서 **HAR-01**을 선택합니다. DRAM 커패시터 모듈에 적합한 장비입니다. NAND 채널·TSV 식각은 별도의 예제 적합 챔버를 사용합니다.
3. `챔버 경유 LOT 추적`에서 해당 챔버를 실제로 지나간 LOT, 발생한 합성 편차, 이후 공정 이력을 확인합니다. 재생 시간을 되돌리면 아직 발생하지 않은 관측은 표시하지 않습니다.
4. LOT 공정 이력에서 식각 → 세정 → 계측 보류를 확인합니다. 보류 이후 공정은 실행되지 않습니다.
5. **이 챔버 제외 후 전체 비교**를 누릅니다. 동일 LOT·투입 시각에서 대체 챔버로 처음부터 재계산합니다. 완료·보류·장비 미배정·LOT당 누적 대기·전체 종료시각을 비교합니다.
6. `변경 전 계획으로 복원`하거나 다른 장비군 조건을 변경합니다. 초안 값은 적용 버튼을 누르기 전까지 결과와 내보내기에 섞이지 않습니다.
7. HBM 적층 정렬 편차, CMP 제거율 저하, 노광 가용성 저하, 기준 운전도 비교할 수 있습니다. HBM 경로는 박막화·다이 분리·정렬·봉지·최종 검토까지 이어집니다.

상단 `투입 계획`에서 LOT 추가·삭제, 제품, 투입 시각, 웨이퍼 수를 수정할 수 있습니다. 투입 구성을 바꾼 비교는 동일 입력 비교와 구분해 표시합니다. LOT을 선택하고 공정 이력의 항목을 누르면 해당 완료 시점으로 이동하며, 아래 수치 근거 표에서 그 장비의 계산 전후 값을 확인합니다.

기본 HAR 이상 예제의 전체 결과는 8 LOT 중 5 완료·3 보류이며, HAR-01을 제외하면 8 완료·0 보류로 계산됩니다. LOT당 누적 대기는 8.5 → 13.375 모형 분으로 증가합니다. 이는 예제의 자원 배정과 규칙 결과이며 실제 공장 성능 수치가 아닙니다.

장비 지도는 8개 공정 구역, 21개 장비군, 48개 가상 챔버를 표시합니다. 장비 클릭으로 역할·관찰 지표·조건을 확인하고, `장비 보기`로 기능 모형을 엽니다. 기존 3D 장비 형상을 재사용하며 전해 도금·박막화·다이 분리·적층·봉지는 별도 SVG 원리 모형을 사용합니다. WebGL이 없는 환경에서는 모든 장비를 SVG로 표시합니다. 원리 동작은 팹 일정과 독립적이며 제조사 제어 시퀀스가 아닙니다.

## 공정과 장비 모델

| 흐름 | 연결된 기능 모듈 |
|---|---|
| DRAM | 표면 준비 → 소자 형성 → 커패시터 → 배선 → 웨이퍼 검토 |
| 3D NAND | 표면 준비 → 소자 형성 → 적층막·채널·게이트 치환 → 배선 → 웨이퍼 검토 |
| HBM 연계 | DRAM 관련 모듈 → TSV → 배선 → 웨이퍼 검토 → 박막화·분리·적층·봉지·최종 검토 |

경로는 기능 설명을 위한 축약입니다. 실제 DRAM·NAND 노드의 상세 구조, 반복 마스크, 정확한 공정 순서, HBM 세대별 기본 다이의 외부 제조 이력은 포함하지 않습니다. TSV 삽입 위치는 실제 통합 방식에 따라 달라지며 이 예제 위치는 특정 기업의 플로우를 의미하지 않습니다.

`memory-fab-engine.js`는 LOT 준비시각 순서로 장비를 선택하는 결정론적 이산 사건 모형입니다. 적합한 챔버 중 가장 빨리 사용 가능한 챔버를 고르고, 하나의 공정에 하나의 LOT을 배정합니다. 공정 종료 후 다음 공정까지 1 모형 분의 이송 간격을 둡니다. 같은 장비에서 공정이 겹치지 않습니다. 이 배정은 최적화 알고리즘이나 실제 디스패치 룰의 재현이 아닙니다.

- HAR-01/02: 커패시터 모듈. HAR-03/04: NAND 채널 모듈. HAR-05/06: TSV 모듈.
- CVD-01/02: 소자·커패시터·배선 모듈. CVD-03/04: NAND 적층·채널 모듈.
- 나머지 장비는 예제 경로 내 공용 자원으로 축약합니다. 실제 재료 교차 오염, 전용 장비, 챔버 qualification은 더 세분화해야 합니다.
- 실제 장비의 배치·웨이퍼 순차 처리·로봇·FOUP·AMHS·PM·고장복구·인력·재작업·Q-time은 모델링하지 않습니다.
- 다이 분리 뒤에도 부모 LOT ID를 유지합니다. 웨이퍼→다이→스택의 수량·분기·수율은 계산하지 않습니다. `200 wafers`는 투입 전 계획 수량입니다.

## 수치 해석

레시피 범위·계수·초기값·처리시간·임계값·LOT ID는 모두 자체 생성입니다. 공개 기술 자료에서 회사 운전값을 추출한 것이 아닙니다. 모델 시간은 **모형 분**으로 표시하며 실제 장비 takt time 또는 팹 cycle time을 뜻하지 않습니다.

구조 상태에는 CD, 마지막 식각 깊이·편차, 마지막 막 두께·편차, 단차, 휨, 정렬, 충진, 파티클 지표 등이 있습니다. 노광/현상 CD는 식각으로, 식각 깊이는 충진으로, 막/식각 조건의 편차 이력은 후속 계측으로, 상류 휨은 적층 정렬로 전달됩니다. 편차 이력은 자동으로 소거되지 않습니다. 예제 규칙을 넘으면 다음 계측 지점에서 보류할 수 있습니다.

일부 입력은 보조 상태만 기록합니다. 이온 주입 도즈·에너지는 주입량·깊이 지표에 기록되지만 전기 특성을 계산하지 않습니다. 계측 `sites`는 표본 계획만 기록하며 실제 위치별 계측·검출 확률·샘플링 오차를 계산하지 않습니다. 장비군 조건은 해당 유형의 모든 챔버와 관련 공정에 공통 적용됩니다. 실제 모듈별 레시피 버전 체계는 후속 과제입니다.

챔버 경유 이력 자체는 인과 증명이 아닙니다. 시연의 원인 표시는 **모델이 주입한 편차와 계산 규칙의 기원**을 알고 있기 때문에 가능합니다. 실제 데이터의 자동 원인 진단 정확도나 AI 신뢰도 수치는 제공하지 않습니다.

보류 때문에 일찍 끝난 계획은 완료 계획보다 처리 작업량이 적습니다. 따라서 두 계획의 종료시간을 직접 생산성 향상률로 환산하면 안 됩니다. UI와 보고서는 이 차이를 표시합니다. 대기 지표는 LOT의 각 공정 대기시간을 누적한 뒤 LOT 수로 나눈 값입니다.

## 보관과 재현

- 별도 브라우저 키: `waferflow-memory-fab-v1`. 기존 `waferflow-fab-v05`, 장비 초안, 서버 DB 기록을 수정하지 않습니다.
- JSON schema: `waferflow-memory-fab-plan-v1`, 모델 `wf-memory-fab-0.1.0`.
- 입력 계획만 저장합니다. 불러오기는 입력과 모델 버전을 검사하고 결과를 다시 계산합니다. 첨부된 임의 결과는 신뢰하지 않습니다.
- 잘못된 입력·단위가 없는 임의 레시피 키·중복 LOT ID·비유한 숫자·허용 범위 밖 값은 거부합니다. 1–40 LOT, 로컬 파일 최대 500 KB.
- HTML 검토 리포트에는 전체 종료 결과, 변경 전후 지표, 두 계획의 재현 입력, 이벤트와 모델 범위를 포함합니다. 로컬 문서이며 승인·전자서명 기록이 아닙니다.

## 실제 기업 파일럿으로 발전시킬 경계

| 단계 | 필요한 입력 | 성공 기준 |
|---|---|---|
| 1. 과거 이력 재생 | 승인된 MES route·LOT/wafer·공정 이벤트, 장비/챔버 식별, 타임존·단위 | 실제 이력과 순서·자원 점유·누락 여부가 일치 |
| 2. 공정 결과 보정 | 동일 LOT/wafer의 레시피 버전·FDC·계측값·규격 버전 | 학습과 별도 검증 LOT의 오차·적용 영역을 제시 |
| 3. 사전 검토 파일럿 | 장비 적합성·PM·Q-time·hold/rework 규칙, 사용자 업무 정의 | 기존 검토 대비 누락 감소·검토 시간·오탐/미탐을 측정 |
| 4. 통합 운영 | 기업 인증·권한·감사·보관·배포 요구 | 실제 운영 기준에 맞춘 보안·복구·성능 검증 |

첫 파일럿은 한 제품의 제한된 모듈과 여러 관련 장비를 대상으로 잡고, 과거 이력 재현을 먼저 검증하는 것이 적절합니다. 전체 팹 프레임은 유지하되 모델을 실측 검증한 영역과 설명용 영역으로 구분해야 합니다. 현재 UI에는 MES/FDC 연결, 실제 장비 명령, 양산 허가 기능이 없습니다.
