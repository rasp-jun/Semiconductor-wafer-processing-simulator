# 장비 레시피·실험 검토 · 사내 파일럿

장비 운전실의 **레시피·실험 검토** 영역에서 사용합니다. 기존의 단일 조직 계정·프로젝트를 공유하고, 장비 운전 근거는 별도의 `equipment_runs` 테이블에 보관합니다. 기존 CMOS 브라우저 기록과 포토 레시피·실험 테이블을 바꾸지 않습니다.

현재 목적은 조건 변경안을 비교하고 근거·의견을 보관하는 사내 파일럿입니다. 현장 장비에서 보정한 모델, 양산 투입 판정 또는 제조사 안전 검증을 제공하지 않습니다. 기록마다 `equipment_validation=not_validated`, `manufacturing_release=false`를 서버에서 고정합니다. 사용자가 JSON에 다른 값을 넣어도 검증 상태로 승격하지 않습니다.

## 업무 흐름

1. 장비 화면에서 조건을 설정하고 계산합니다. 기본 합성 모델과 사용자 로그를 구분합니다.
2. **현재 기록을 비교 기준으로**를 눌러 기준을 고정한 뒤 조건을 바꿔 다시 실행합니다. 같은 단계의 시간 가중 평균·차이·데이터 커버리지와 레시피 변경을 확인합니다.
3. **계정 연결**로 로그인합니다. 최초 관리자·구성원 설정은 기존 `workbench.html`에서 합니다. 기본 계정·비밀번호를 자동 생성하지 않습니다.
4. 프로젝트를 선택하거나 만듭니다. **검토 기록 보관**에서 검토 이름, Lot/시편, 출처, 검토 목적·변경 사유를 입력합니다. 창을 연 시점의 계산 전체를 고정합니다. 미실행 초안이나 현재 재생 위치를 운전 결과로 보관하지 않습니다.
5. 작성자는 저장한 r1을 **검토 요청**합니다. 다른 관리자 또는 검토자가 의견을 남기고 **검토 완료**하거나 **반려**합니다. 작성자는 관리자여도 자기 기록을 검토 완료할 수 없습니다.
6. 변경이 필요하면 기록 상세의 **조건을 불러와 새 버전 작성**을 누릅니다. 조건 변경 → 실행 → 보관으로 r2를 만듭니다. 이미 새로운 버전이 있으면 오래된 기준의 저장 요청은 충돌로 거절됩니다.
7. **이 기록 보고서**는 선택한 서버 기록, 보관 당시 연결한 기준 기록, 검토 상태·의견·해시를 사용합니다. **현재 계산 보고서**는 별도의 로컬 보고서이며 서버 검토 상태를 붙이지 않습니다.

검토 요청은 앱 내부 상태 변경이며, 이메일·메신저 알림을 보내지 않습니다. 보고서는 외부 스크립트·폰트 없이 열 수 있는 HTML입니다. 인쇄 CSS는 포함하되 실제 브라우저 인쇄 배치는 아직 확인하지 않았습니다.

## 보관·무결성

- 운전 로그, 출처 선언, 변경 사유, 작성자, 부모 버전, 비교 기준은 저장 후 수정·삭제할 수 없습니다. 데이터베이스 트리거로 내용 변경을 막습니다. 검토 상태와 의견만 정해진 API로 갱신합니다.
- 서버가 로그를 검증·정규화하고 SHA-256 및 요약을 계산합니다. 해시는 **보관한 정규화 로그**의 내용 식별자이며 원본 파일의 바이트 해시나 제조사 인증·전자서명이 아닙니다.
- 파일·브라우저에서 제출한 로그는 서버에서도 원출처 미검증으로 취급합니다. 클라이언트가 주장하는 통과 상태·실측 인증을 신뢰하지 않습니다. 기록상의 결과와 장비 적합성 검증을 분리합니다.
- 작성·제출·검토 완료·반려를 기존 append-only 감사 테이블에 기록합니다.
- 요청 식별자를 통해 같은 저장 요청의 재전송을 중복 생성하지 않습니다. 같은 식별자로 다른 내용을 보내면 충돌로 처리합니다.
- 검토 전이는 `lock_version`으로 동시 수정을 확인합니다. 동료가 먼저 상태를 바꾸면 새로고침 후 다시 검토합니다.
- 신규 테이블은 `server/equipment-schema.sql`로 추가하고, 기존 스키마를 덮어쓰지 않습니다. 기존 백업 도구는 신규 테이블도 함께 보관합니다.

## 비교 해석

장비 프로필 ID와 모델 버전이 같고, 양쪽에 선택한 단계의 시간 구간이 있어야 수치를 비교합니다. 단위가 다르면 비교하지 않습니다. 샘플 간에는 이전 기록값이 유지된 것으로 계산합니다. 단계가 바뀌는 시점까지 이전 단계의 구간으로 집계하며 마지막 샘플에는 지속 시간을 추가하지 않습니다.

평균 = Σ(기록값 × 다음 샘플까지의 시간) / 값이 제공된 구간의 총시간입니다. 채널이 누락된 구간을 0으로 채우지 않습니다. 커버리지는 채널 값이 제공된 시간 / 해당 단계 시간입니다. 긴 샘플 간격이나 누락 때문에 평균 해석이 제한될 수 있습니다. 표의 숫자는 통계적 유의성, 공정능력, 수율 또는 규격 합격 판정이 아닙니다. 단계 길이가 다른 경우 현재·기준 시간을 함께 확인합니다.

## 역할과 API

| 역할 | 가능한 작업 |
|---|---|
| engineer | 전체 프로젝트 열람, 기록 보관, 새 버전 작성, 본인 초안 검토 요청 |
| reviewer | 전체 프로젝트 열람, 다른 작성자의 제출 기록 검토 완료·반려 |
| admin | 위 관리·작성·검토 기능. 본인 기록의 자기 검토는 불가 |

| 경로 | 역할 |
|---|---|
| `GET /api/equipment/capabilities` | 보관 한도·범위·단위 |
| `GET /api/equipment/runs?project_id=…&offset=…` | 30개씩 목록·총개수. 전체 로그 제외 |
| `POST /api/equipment/runs` | 새 검토 기록 또는 부모 버전 기반 새 버전 |
| `GET /api/equipment/runs/<id>` | 전체 로그·해시·검토 상태 |
| `POST /api/equipment/runs/<id>/transition` | `submit`, `review`, `reject` |

모든 경로에 기존 세션 인증을 적용합니다. 쓰기는 CSRF 토큰과 검증 헤더를 요구하며 역할·작성자·버전을 서버에서 확인합니다. 요청당 최대 1.4 MB, 샘플 2–15,000개, 시간 0–1,800초입니다. 브라우저에서 파일을 읽는 8 MB 한도와 서버 보관 한도는 다릅니다. 큰 로그는 원본을 별도 보관하고 적절한 구간을 선택해 정규화해야 합니다. 자동 단위 추정이나 PHM 원본 파싱은 제공하지 않습니다.

모든 로그인 사용자는 같은 조직의 전체 프로젝트를 열람합니다. 프로젝트별 비밀 구분, 다중 조직, SSO/MFA, 고객별 권한, 인증된 전자서명, HA 및 대규모 장기 로그 보관은 구현하지 않았습니다. 현장 도입 범위가 이를 요구하면 파일럿 이후 해당 요구를 구현·검증해야 합니다. 장비 제어 명령은 전송하지 않습니다.

## 실행·검증

`python run_server.py --port 8769`로 업데이트한 서버를 실행하고 `http://127.0.0.1:8769/equipment.html`을 엽니다. 계정과 프로젝트 DB는 기존 경로를 사용합니다. 브라우저 로컬 저장은 포트별로 다르므로 기존 CMOS 기록은 원래 주소에서 확인합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_equipment_review tests.test_review -v
node --input-type=module -e "import('./tests/equipment-review-tests.mjs').then(async m => console.log(await m.runEquipmentReviewTests(process.cwd())))"
```

실제 HTTP 통합 시험은 `python -m tests.equipment_http_server`의 임시 8771 서버를 시작하고 45초 이내에 `tests/equipment-http-ui.mjs`의 `runEquipmentHTTPUI(root)`를 실행합니다. 테스트 계정은 임시 DB에만 만들고 서버는 자동 종료합니다. 실제 작업 DB나 사용자 계정을 시험에 사용하지 않습니다.
