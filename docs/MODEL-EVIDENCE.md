# 공정 모델 근거 검증

`evidence.html`은 실제 측정 자료를 받았을 때 오차를 검토할 수 있는 로컬 작업 공간입니다. 메모리 팹의 `모델 근거 검증` 메뉴와 HAR·CVD·CMP 장비 카드에서 진입합니다. 실제 기업 자료는 현재 포함되어 있지 않습니다.

## 지원 범위

| 응답 | 팹 계산과 공유하는 기준 항 | 입력 단위 |
|---|---|---|
| HAR 식각 깊이 | 목표 깊이 × (파워/1000)^0.25 × (시간/120) × (15/압력)^0.08 | nm, W, s, mTorr |
| CVD 막 두께 | 목표 두께 × (유량/100) × √(온도/400) | nm, sccm, °C |
| CMP 잔여 단차 | max(1, 입력 단차 × (1 − 압력/3 × rpm/60 × 시간/60) + 2) | nm, psi, rpm, s |

이 식과 계수는 기존 **미보정 예제 모델**의 기준 응답입니다. 물리 법칙으로 입증된 제조사 식이 아닙니다. `MemoryFab.referenceResponse`를 팹 계산과 검증 공간에서 함께 사용합니다. LOT ID로 만든 합성 변동과 이상 주입은 검증의 기준 응답에 넣지 않습니다.

이 공간에서 추정하는 것은 기준 출력 `x`를 계측값에 맞추는 `y = a × x + b` 또는 `y = x + b`입니다. 가스 반응·재료 특성·RF 응답 계수 자체를 식별하거나 전체 팹을 보정하는 기능은 아닙니다. 일정·불량 전파·전기 수율·계측 불확도·장비 안전은 검증하지 않습니다.

## 사용 순서

1. 응답 종류를 고르고 `빈 양식`을 내려받습니다. JSON만 지원합니다. 양식의 측정값과 입력 조건은 `null`이며 실제 값으로 채워야 합니다.
2. 한 제품·공정·장비·챔버·레시피 범위의 자료를 입력합니다. 위치별 계측이 여러 개라면 정의한 집계 방식으로 웨이퍼별 한 값으로 합치고, `metrologyMethod`에 방법을 기록합니다.
3. `계측 JSON 불러오기`로 읽습니다. 단위·필수값·ID·중복·시각을 검사하며 잘못된 행을 조용히 버리지 않습니다.
4. 결과를 보기 전에 보정 방식, 과거 LOT 비율, MAE·절대 평균 편향·최대 오차 기준을 정합니다. 기본 허용 오차는 **시연용 예제**로 현장 규격이 아닙니다.
5. `계획 고정`을 누릅니다. 과거 LOT만으로 계수를 계산합니다.
6. `후속 LOT 검증`을 누릅니다. 이후 LOT에서 기준 모델과 보정 모델의 오차를 비교합니다.
7. 잔차, LOT별 오차, 범위 밖 입력, 출처, 검증 자료 재사용 여부를 함께 확인합니다. 새 조건 미리 계산은 보정 범위와 대상 장비가 맞는지 확인하는 참고 기능입니다.
8. JSON 검토 패키지와 HTML 리포트를 내려받습니다. 패키지에는 계측 원본이 포함됩니다. 패키지를 다시 불러오면 자료·계획 지문을 확인하고 결과를 재계산합니다.

## JSON 데이터 계약

스키마는 `waferflow-process-evidence-v1`, 응답 모델은 `wf-response-0.1.0`입니다. 최대 4 MB, 5,000개 관측을 받습니다. 값은 숫자여야 하며 숫자 문자열, null, NaN, 무한대는 사용할 수 없습니다. `0`은 지표의 허용 범위 내에서 실제 값으로 취급합니다.

```json
{
  "schema": "waferflow-process-evidence-v1",
  "modelVersion": "wf-response-0.1.0",
  "datasetId": "EXAMPLE-DATASET-ID",
  "profile": "har",
  "scope": {
    "product": "dram",
    "referenceStepId": "C02",
    "sourceStepId": "YOUR-PROCESS-STEP",
    "equipmentId": "YOUR-EQUIPMENT",
    "chamberId": "YOUR-CHAMBER",
    "recipeRevision": "YOUR-RECIPE-REVISION",
    "metrologyId": "YOUR-METROLOGY",
    "metrologyMethod": "Describe wafer-level measurement aggregation"
  },
  "origin": {"kind": "user-measurement", "source": "Describe the source export"},
  "units": {"target_nm": "nm", "power_w": "W", "pressure_mtorr": "mTorr", "time_s": "s", "measured": "nm"},
  "observations": [{
    "id": "OBS-001", "lotId": "LOT-001", "waferId": "W01", "runId": "RUN-001",
    "processedAt": "2026-01-01T01:00:00+09:00",
    "measuredAt": "2026-01-01T02:00:00+09:00",
    "inputs": {"target_nm": null, "power_w": null, "pressure_mtorr": null, "time_s": null},
    "measured": null
  }]
}
```

위 예시는 채워야 하는 **형식 설명**으로 그대로 계산할 수 없습니다. 앱의 합성 예제는 `origin.kind=synthetic`으로 생성합니다. 사용자 자료의 `user-measurement`는 사용자 선언이며 인증이 아닙니다. 어떤 입력에서도 `sourceVerified`나 `manufacturingRelease`가 true가 되지 않습니다.

`referenceStepId`는 현재 축약 팹 경로의 해당 장비 공정이어야 합니다. 실제 공정 ID는 `sourceStepId`에 별도로 보관합니다. 동일 데이터셋 안에서 장비·챔버·제품·레시피·계측 방식이 바뀌었다면 별도 데이터셋으로 나눠야 합니다.

## 분리·보정·오차 계산

- LOT을 최초 공정 완료 시각으로 정렬하고 앞의 60/70/80%를 보정, 나머지를 검증으로 둡니다. 한 LOT의 모든 관측은 한쪽에만 포함됩니다.
- 가장 늦은 보정 계측 완료 시각이 최초 검증 공정 완료보다 빨라야 합니다. 이 조건을 어기면 계획 고정을 거부합니다. 실제 예측 시점이 공정 시작이라면, 현장 데이터 계약을 시작 시각 기준으로 확장해야 합니다. 현재 자료는 **공정 완료 이후 계측 전 응답 평가**의 시간 경계입니다.
- 보정 최소 6 LOT, 검증 최소 3 LOT은 기능상의 예제 최소치입니다. 통계적 충분성이나 공정 qualification 기준이 아닙니다.
- 각 보정 LOT의 기준 출력과 계측값을 각각 평균하고, LOT 평균 점들에 같은 가중치로 최소제곱 직선을 맞춥니다. 웨이퍼 관측 수가 많은 LOT이 계수 추정을 과도하게 지배하지 않게 합니다.
- 기울기 추정에 필요한 기준 출력 변화가 없거나 기울기가 양의 유한값이 아니면 보정을 거부합니다. 오프셋만 보정할 수는 있지만 이 또한 모델 적합성을 보장하지 않습니다.
- 검증 잔차는 `예측 − 계측`입니다. MAE=평균 절대 잔차, RMSE=제곱 잔차 평균의 제곱근, 편향=평균 잔차, 최대 오차=최대 절대 잔차입니다.
- P95는 관측 절대 잔차의 선형 보간 95백분위입니다. **신뢰구간이 아닙니다.** LOT 평균 MAE도 별도로 표시합니다.
- 기본 지표에는 범위 밖 값과 큰 오차를 포함한 모든 검증 관측을 사용합니다. 모델에 유리한 값만 남기는 필터는 없습니다.
- 각 입력과 기준 출력의 보정 최소·최대 범위 밖 관측이 있으면 범위 점검은 실패합니다. 축별 범위 내라는 사실은 다변량 조합의 적합성이나 일반화 성능을 보장하지 않습니다.
- 잔차 도표는 최대 200개 관측을 순서 전체에서 고르게 표시합니다. 표 화면도 최대 200행이며 통계·패키지·보고서에는 전체 검증 관측을 포함합니다.

## 근거 보관과 재사용

정규화 데이터, 원본 입력 파일(있는 경우), 고정 계획에 SHA-256 지문을 남깁니다. 이는 내용 식별과 우발적 변경 확인용으로 전자서명·장비 인증·서버 감사 기록이 아닙니다.

자료를 브라우저 저장소나 서버에 자동 저장하지 않습니다. 검토 패키지를 내려받지 않고 새로고침하면 현재 자료는 사라집니다. 브라우저 저장소 `waferflow-evidence-ledger-v1`에는 데이터·검증 LOT 내용의 해시와 평가 횟수·시간만 기록합니다. 기존 팹·장비 기록은 수정하지 않습니다.

동일 데이터 또는 동일 검증 LOT을 다시 평가하면 탐색 결과로 표시합니다. 데이터 이름을 바꾸거나 다른 보정 LOT을 수정해도 동일 검증 LOT 재사용을 확인합니다. 최근 3,000개 지문까지만 유지하며, 다른 브라우저·삭제된 저장소·식별자 또는 내용이 바뀐 자료의 전체 재사용 이력까지 증명할 수는 없습니다. 로컬 이력을 읽지 못한 경우 독립 검증으로 표시하지 않습니다. 계획을 변경해 기존 검증 결과를 반복 확인했다면 새로운 기간의 LOT으로 추가 시험이 필요합니다.

검토 패키지 스키마는 `waferflow-evidence-review-v1`입니다. 불러올 때 입력과 재계산한 계획의 지문을 비교합니다. 캐시된 결과나 합격 플래그는 사용하지 않습니다. 같은 자료를 다시 검토한 사실은 표시하되 양산 승인을 부여하지 않습니다.

## 공개 방법론 근거

- [NIST: 잔차를 통한 모델 검토](https://www.itl.nist.gov/div898/handbook/pri/section6/pri619.htm) — 잔차의 크기와 구조·시간 순서 패턴을 살펴보는 접근을 참고했습니다.
- [scikit-learn: 그룹 및 시간순 검증](https://scikit-learn.org/stable/modules/cross_validation.html) — 같은 그룹의 관측을 분리하지 않고 미래 정보가 과거 모델로 섞이지 않도록 하는 원칙을 참고했습니다.

자체 JavaScript 구현입니다. NIST 인증, scikit-learn 라이브러리 실행 또는 특정 기업의 검증 기준을 주장하지 않습니다.

## 재현 가능한 검사

Node 22 이상, Python 가상환경에서 다음을 실행합니다. 테스트용 자료는 코드에서 생성하며 사용자 파일을 사용하지 않습니다.

```powershell
node tests/run-all.mjs
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
```

JavaScript 검사에는 공정 계산·장비 형상(렌더러 대역)·DOM 동작·수치 검증이 포함됩니다. 실제 브라우저 레이아웃, GPU 시각 품질, 실장비 예측 정확도는 이 검사로 입증하지 않습니다.
